# freelance-marketplace

Биржа фриланса (проекты + отклики) для Кыргызстана, СНГ и Европы. Языки: русский, английский.

## Структура

```
apps/api         NestJS + Prisma + PostgreSQL (REST, /api/*)
apps/web         Next.js 15 + next-intl (/ru, /en)
packages/shared  общие роли, расчёт комиссии, версии юр. документов
apps/web/content/legal/{ru,en}  тексты соглашения, оферты, политик (ЧЕРНОВИКИ)
```

## Запуск в Docker (весь стек)

```bash
cp .env.example .env        # один раз; задать JWT_SECRET
docker compose up -d --build
docker compose exec api npm run admin:create   # один раз: создать админа
```

Сайт — http://localhost:3100. Снаружи открыт только nginx (`deploy/nginx.conf`): он проксирует `/api` в API,
остальное во фронт. API и база наружу не публикуются (база — только `127.0.0.1:5432`). При старте API сам применяет
миграции и создаёт категории. После изменений в коде повторите `docker compose up -d --build`.

## Локальная разработка

```bash
cp .env.example .env        # задать JWT_SECRET
npm install
npm run build:shared
npm run db:up               # Postgres в Docker
npm run db:migrate          # миграции
npm run db:seed             # категории
npm run admin:create -w @fm/api   # создать админа (email и пароль вводятся в терминале)
npm run dev:api             # http://localhost:4000/api
npm run dev:web             # http://localhost:3000
```

Тесты расчёта комиссии: `npm test`.

## Роли

| Роль | Как получить | Возможности |
|---|---|---|
| ADMIN | `npm run admin:create` | всё + назначение ролей, статистика, ручное подтверждение оплаты |
| MODERATOR | назначает админ в `/admin` | жалобы, скрытие проектов, блокировка пользователей, споры, журнал действий |
| EMPLOYER | регистрация | проекты, выбор исполнителя, приёмка, споры |
| FREELANCER | регистрация | отклики, выполнение заказов, споры |

## Учётные данные

Логины и пароли нигде не хранятся в файлах и переменных окружения: только хэш пароля (bcrypt) в БД.
Первый админ создаётся командой `admin:create`, которая спрашивает email и пароль в терминале
(повторный запуск с существующим email делает его админом и сбрасывает пароль).
Дальше email и пароль меняются на сайте в разделе «Настройки» (`/settings`). Смена пароля
завершает все остальные сессии пользователя.

## Безопасность

- **Вход:** nginx выставляет реальный IP клиента (подменить `X-Forwarded-For` нельзя), ограничивает
  частоту запросов и соединений с одного IP, обрывает медленные соединения, тело запроса до 1 МБ.
- **API:** лимиты частоты по IP и по маршрутам (вход и регистрация — 10/мин, проекты, отклики,
  сообщения, жалобы — свои лимиты), блокировка пары «email + IP» на 15 минут после 10 неверных паролей (чужой IP не может
  заблокировать владельца), не больше 4 одновременных вычислений bcrypt,
  одинаковое время ответа для существующих и несуществующих email, проверка Origin (CSRF),
  ограничения длины всех полей и размера выдачи списков, тело JSON до 100 КБ.
- **Данные:** комиссия не видна работодателю, IP и детали изменений в журнале видит только админ,
  модератор не может отменить блокировку или скрытие, сделанные админом, споры решаются атомарно,
  персонал не пишет в чужие чаты и не решает споры по своим заказам. Роль ADMIN выдаётся и снимается
  только командой `admin:create` на сервере, через API её не изменить.
- **Поиск:** триграммные индексы (`pg_trgm`), серверный рендер передаёт IP посетителя в API, лимит
  страниц — 100.
- **Веб:** CSP, запрет встраивания во фреймы, HSTS, nosniff, Referrer-Policy.
- **Инфраструктура:** контейнеры работают не от root, `JWT_SECRET` короче 32 символов не принимается.
- **Перед запуском в продакшн:** HTTPS (и `COOKIE_SECURE=true`), свой пароль БД вместо `fm/fm`,
  внешняя защита от DDoS (Cloudflare или аналог), бэкапы БД.

## Комиссия

Удерживается с исполнителя, одна ставка на весь заказ по сумме этого заказа:
менее 30 000 сом — 20%, от 30 000 до 300 000 — 12%, 300 000 и более — 7%.
Ставка фиксируется в заказе при его создании (`packages/shared/src/commission.ts`).

## Жизненный цикл заказа

`AWAITING_PAYMENT → IN_PROGRESS → SUBMITTED ⇄ REVISION → COMPLETED`, плюс `CANCELLED` и `DISPUTED`.
Допустимые переходы — `apps/api/src/orders/order-transitions.ts`. Работа, не проверенная за
3 дня (`AUTO_ACCEPT_DAYS`), принимается автоматически (cron каждые 10 минут).

## Платежи

Пока только модели данных (`Payment`, `Wallet`, `LedgerEntry`, `PayoutMethod`, `Payout`),
оплату подтверждает админ вручную. Места для интеграции помечены `TODO(payments)`.

## Юридические документы

Тексты в `apps/web/content/legal` — черновики с плейсхолдерами `[...]`. До запуска их
должен проверить юрист в КР. Принятие документов при регистрации записывается в
`UserConsent` (документ, версия, IP, user-agent, время). При изменении текста поднимите
версию в `packages/shared/src/legal.ts`, и пользователи увидят запрос принять новую редакцию.
